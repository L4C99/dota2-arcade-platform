# Platform v1.0.2 Core v0.1.2 alignment amendment

Status: **Owner-approved narrow dependency-baseline amendment**, 2026-09-30. Applies to upcoming Platform v1.0.2 and I4 onward; this is neither I4 implementation nor deployment/release authorization.

## Decision

Platform v1.0.2 changes its exact fixed d2core release from `v0.1.1` / `988720ad85af1f0d97bfe98ec4da4fcbb070beea` to `v0.1.2` / `6dddb5892f962e70beb32fc30df4a78bce595528` (dereferenced publication commit). Core local protocolVersion remains **1**, template schemaVersion **1**, disk formatVersion **2**. Node API remains **1**, migration **22**; no migration is added or edited.

The old and new Core commits have identical `client/`, `cmd/` and `internal/` Git trees and unchanged `go.mod/go.sum`. The delta consists of release hardening, packaging/provenance, licensing, CI, docs and example template values. Runtime/client signatures and behavior, local protocol, lifecycle/create/restart/stop, operation/status/list, idempotency, persistence/recovery, reclaim and readiness matching are unchanged. Platform business flows continue not to call instance restart.

Heartbeats with Core version `0.1.2` (or the historically supported `v0.1.2` spelling), exact commit and verified protocol 1 are compatible only with Node API 1. Core v0.1.1, other versions/commits and other/unverified protocols are incompatible. Core compatibility does not grant a capability session or weaken old-Controller request fences.

## Unchanged authority and safety

This amendment changes only the fixed release identity in [frozen V1](v1.md) and [v1.0.2 content maintenance contract](v1.0.2-content-maintenance-validation.md). Their original text remains point-in-time history. All functional semantics and acceptance conditions remain in force, including [execution-fence amendment](v1.0.2-execution-fence-amendment.md), FIX-05, operation-start MAY-HAVE-STARTED accounting, unknown/quarantine capacity retention and full reclaim predicates. A later no-ID rejection cannot fence an earlier delayed/unknown create.

Scheduler, ValidationRun, release.publish, B-M1, Node × ArcadeGame gate, Content Tool, database schema, Player/Admin APIs and Web product behavior are unchanged. Historical validation records retain the actual v0.1.1 baseline used at their recorded time, as do published changelog entries and historical licensing clarification.

I4 and later acceptance must use Platform v1.0.2 + Core v0.1.2. Deployment/Production access, merge, Platform tag/Release and independent focused compatibility review require separate Owner authorization. This alignment candidate stops before those actions.

Evidence and checks: [alignment validation](../validation/v1.0.2-core-v0.1.2-alignment.md).
