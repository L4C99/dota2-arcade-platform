# P5E operations checkpoint

`docs/operations.md` now covers protected PostgreSQL backup/disposable restore, explicit migration and failed-migration refusal, versioned Platform/Web update and code-only rollback, one-node-at-a-time Controller update, fixed d2core and manual Dota maintenance, Content Tool switching/rollback, unknown-effect reconciliation and human trials. `deploy/scripts/backup-postgres.sh` uses a private libpq service file, writes a mode-0600 custom-format dump, validates its table of contents and refuses to overwrite an existing backup.

Development verification on 2026-09-26:

- Before the Platform update, the backup script created a protected 157,430-byte dump with SHA256 `ae755c0d9c3408a45d04852ddc034a4e11ee2ca9af33e5f432fd5968781754a5`. It restored into a **separate disposable database**. Source and restored counts for ArcadeGame, ServerRequest, Allocation and Audit were both `2|63|60|134`. The disposable database was removed after verification; the restricted backup was retained outside Git.
- No Allocation, open NodeJob or active ServerRequest existed when the exact clean `804109f` Platform/Web build replaced `6a6dfd8`. Explicit `migrate` reported current; public HTTPS health, homepage and hashed JS returned 200. A guarded rollback briefly restored `6a6dfd8`, passed health, then returned to `804109f` and passed health again. The old binary/Web/launcher remain available. This was a code-only rollback with no schema reversal.
- Both Controller updates used Node Drain, zero occupied Allocations/open Jobs and empty direct d2core lists. Linux and Windows were updated separately to exact clean `804109f` artifacts; old binaries remained. Reconcile completed Linux generation 9/9 and Windows 6/6. Both nodes returned to compatible fresh heartbeats with unchanged ContentVersion bindings, URI entry flags false and Drain cleared. The Windows stop command initially waited for a cross-user PowerShell confirmation; no process stopped then. The exact old process identity was rechecked, and a noninteractive exact-PID stop completed before the new Controller started.
- P5B had already exercised the old game's two-node immutable content rollout and preserved the previous P1 release on each node as the rollback target. No live content hot switch was performed during this operations drill.

**NOT VERIFIED:** A deliberately failing migration and recovery from a schema-incompatible old binary, a real d2core or Dota upgrade (outside this stage's authorization), actual Content Tool rollback on a live development node, production recovery and unattended Windows task restart. The documented recovery path does not treat a restored business row as proof that a d2core instance stopped. The authorized development backup, binary update/rollback and two-node Controller rolling-update checks passed.
