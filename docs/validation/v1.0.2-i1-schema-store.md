## IMPLEMENTED

### Migration 0020

- Added `validation_runs` with candidate identity, Admin origin, fact/maintenance generations, human result, evidence times, status and failure/result fields. Candidate identity and terminal history cannot be rewritten. A deferred constraint requires each committed Run to have exactly one Allocation and one create Job.
- Extended `allocations` with `purpose` and `validation_run_id`, made `server_request_id` nullable only for validation ownership, enforced player/validation owner XOR, fixed validation attempt sequence to one, and extended the immutable identity trigger. Existing rows default to `player`; the existing player uniqueness and occupied predicate remain in place.
- Added `maintenance_epoch` and `content_fact_revision` to content bindings; expected template fingerprint and `binding_generation` to template bindings; a separate Controller-reported `node_template_facts` table; and a binding-generation trigger that rejects changes inconsistent with binding identity changes.
- Added immutable maintenance request records, inventory snapshots and per-instance identities, with scan ID uniqueness, completion/state distinction and unaccounted summaries.
- Added immutable NodeJob `required_capability` and frozen execution inheritance plus optional template manifest identity. Historical Jobs default to `legacy_v1`. A validation Job must require `content_validation_v102`; legacy prepare cannot freeze it without manifest evidence.
- Added `game_presets.validation_contract` with legacy backfill, `v1_0_2` default for new rows and no downgrade; additive `content_releases` and per-preset history tables for I3. Historical `content_release_validations` is unchanged and is not promoted into Run PASS.
- Migrations `0001`–`0019` were not edited. The migration test compares their recorded SHA-256 checksums across the upgrade.

### Store

- Added scoped `BeginScopedMaintenance` with Node serialization, epoch CAS, request-ID idempotency, binding close and audit. It does not Drain the whole Node or stop an instance. `ScopedMaintenanceStatus` reports target-game resources separately from total Node occupancy.
- Added candidate reserve as one transaction: current content/template/inventory facts and scoped drain are rechecked under the Node lock, shared occupied capacity is checked, then Run, capacity-occupying Allocation and pending create Job commit together.
- Added template binding/fact updates with revision or generation changes only when final identity/state changes. Heartbeat content facts now compare preceding and final state; identical reports only refresh receipt time, including repeated missing/unknown reports.
- Added complete/partial inventory persistence and accounting to nonterminal Allocation/create-Job identities. Partial and duplicate scans cannot supply an empty proof.
- Added Run reads and status progression through existing create/stop reports and instance facts, audited human confirmation, formal stop creation, final PASS after current fact and full resource proof, and FAIL after a proved no-effect or full reclaim. Unknown and quarantine retain capacity.
- Legacy `content.validate` and `content.publish` reject a game with any `v1_0_2` preset or release history inside their transaction. Legacy games retain the old path.

### Lock order

- Added a shared Request → NodeJob (ID order) → Allocation locking helper with relation rechecks. Report paths take needed public Node/fact locks before Job/Allocation.
- Reordered `ReportJob`, `ReportInstanceFact`, `PrepareCreate`, player stop/next-game, Admin request stop, Admin pending termination and quarantine, automatic/CLI quarantine and reclaim-related transitions. Next-game intent is written after Job/Allocation state changes.
- Removed the pre-Request User row lock from stop/next-game and abandon, then rechecks current owner authority after locking Request. A PostgreSQL forced interleaving initially reproduced a User/Request FK deadlock; the repaired interleaving passed repeated runs.
- Admin binding and template-binding updates now lock Node before their binding row.
