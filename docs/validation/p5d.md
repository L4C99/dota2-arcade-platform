# P5D reference deployment checkpoint

The repository provides an Ubuntu 24.04 LTS amd64 Web control-plane reference with Caddy TLS, native Platform Server/systemd, PostgreSQL, Web assets, explicit migrations, health, persistent paths, separate environment/Secret files and versioned rollback. Linux and Windows Controller installation assets keep d2core and Controller under one ordinary account and derive the manager's port bounds from the Controller JSON. Docker Compose is not required. These are reference assets, not a production deployment.

Development verification on 2026-09-26:

- The existing Web host is Ubuntu 24.04.1 LTS. An exact clean Platform/Web build from `804109fb08a292eb61298f7652fd09ead0754067` was installed outside the source tree after explicit `migrate` reported current. Public HTTPS health and the served Web HTML/JS returned 200; the previous binary, Web root and launcher were retained.
- The Linux game node is Ubuntu 24.04.3 LTS. Its actual Controller config has local ports 28000–28009; the running d2core manager uses exactly `--port-min 28000 --port-max 28009`, with the Controller and manager under `steam-fetch`. Fixed d2core `BUILD.json` reports v0.1.1 and commit `988720ad85af1f0d97bfe98ec4da4fcbb070beea`. The shell wrapper passed `bash -n`. `systemd-analyze verify` parsed both reference units but reported their `/opt/dota-arcade-node/current` executables absent because the development runtime uses `/srv/arcade-dev/game`; this was not a service-install test.
- The Windows development VM's actual config has ports 28100–28109; its running manager uses those exact bounds. Both manager and Controller run as `d2coretest`, with four template bindings and two content bindings. The official `install-node.ps1 -ValidateOnly` passed on the real config and fixed d2core manifest. No startup task or service was registered by that preflight.
- Both development Controllers were subsequently updated one node at a time to clean build `804109f` with Drain, empty d2core list, versioned binary, restart, Controller reconcile, compatible fresh heartbeat, unchanged content facts and Resume. The Windows Controller remains in a foreground SSH session, as in the pre-existing development setup; this does not exercise unattended task startup.

**NOT VERIFIED:** A fresh Ubuntu installation of the reference systemd units, Windows startup-task registration and unattended reboot, production TLS/Secret provisioning, and production deployment. Those paths require a later installation exercise; P5D reference implementation and development preflight are complete, while unattended installation acceptance remains open.
